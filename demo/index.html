What is happening
Two checks run, and they answer different questions. Tracked files are re-hashed and compared against the stored manifest, so a changed byte in any of them is flagged. The knowledge tree is separately re-hashed from leaf content upward, so an edited claim is flagged even if no file was added or removed. Either one failing sets the status to MODIFIED.

Neither check can tell an authorised edit from tampering. What they establish is that the bytes moved since the manifest was last written. And the check cannot vouch for the code running it — server.py hashes itself, so a tampered server.py could simply report OK; catching that means comparing the hashes independently, from outside this page.
Workspace
In this demo the memory layer is the demo/ directory: demo_tree.json holds the knowledge tree, demo_manifest.json is the baseline the file check compares against, and demo_synapses.json holds the relationships between claims. In a deployment this is the persistent store the agent reads before answering — the claims, their confidence, and what contradicts them.

Tamper-evident, not tamper-proof: the checks tell you the bytes changed, not who changed them or whether they were allowed to.
